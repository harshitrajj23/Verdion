## 1. Executive Summary

Legal intelligence outputs must never misrepresent their computational origin. If an analysis was generated by a deterministic rule engine rather than a multi-billion parameter LLM, the system must explicitly disclose this fact. Token usage, model identifiers, provider names, and inference latencies must be honest and verifiable.

This audit traces representative persisted agent outputs across `cases`, `claims`, and `forecasts` to determine their exact creation path.

## 4. Elimination of Client-Side Mock Fallback

Prior to Phase 5A, if a user triggered `commitForecast` or `settleMarket` in `frontend/src/lib/store.tsx` while the backend was unavailable:
- The client `catch` block caught the error, called `generateTxHash()`, set status to `"CONFIRMED"`, and reported offline success.
- **Remediation in Phase 5A:**
  - Deceptive catch blocks were deleted.
  - Failed requests mark the pending transaction as `"REVERTED"` and throw the actual network error.
